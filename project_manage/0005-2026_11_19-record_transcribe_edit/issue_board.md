## 2. 배경
### 2-1. 배경
- 앱의 첫 쓸모는 녹음을 기기 안에서 받아쓰고 사람이 틀린 곳을 고치는 것이다, 사람이 발화 그대로라고 확인한 구간만 학습한다(프로젝트 PD13)
### 2-2. 목표
- 데스크톱에서 녹음하거나 음성 파일을 불러와 받아쓰고, 조각을 고치고, 다시 열어도 남는다
### 2-3. 구현 방향
(이미 정해진 것, 출처 프로젝트 `project_manage/project_decision.md`)
- PD5: Rust, Tauri 2, Leptos, PD10: 첫 판은 녹음, 받아쓰기, 수정까지이고 화자 칸만 둔다
- 받아쓰기는 #3 의 `Transcriber` interface 로만 부른다, 엔진과 모델은 #3 의 추천과 프로젝트 PD9 를 따른다
- 저장은 interface(repository) 뒤에 둔다, 자동 전사, 일반 편집본, 발화 그대로라고 확인한 전사를 따로 보존한다. 오류 위치를 찾는 빠른 검수와 전사 교정을 별도 화면 흐름으로 둔다
- 음성과 글은 기기 밖으로 보내지 않는다, 밖으로 나가는 통신은 모델 파일을 처음 받는 것 하나뿐이고 받는 주소와 받은 파일의 해시 확인을 코드에 둔다
### 2-4. 해치지 말아야 할 것, 기존 구현 의도
- #1 의 CI 다섯 플랫폼 빌드가 계속 통과한다, 폰에서 아직 안 되는 기능은 그 플랫폼에서 꺼 두고 README 에 적는다

## 8. 수정 요약
- 빠른 검수 화면은 원본 음성을 30초씩 받아 이어 재생한다. 오류 후보는 실제로 들은 최대 6초다. 좌우와 Enter로 범위를 좁히고, 위쪽 화살표로 다른 갈래에 갈 때 오류를 보관한다. Esc는 찾은 오류를 한 번에 저장한다
- 탐색 화면의 원본 스펙토그램, Whisper가 시간에 맞춘 전사 글자, 깊이별 오류 범위는 원본의 정수 표본 번호로 정렬한다. 글자 시각이 없는 전사는 줄 범위에 표시한다
- 데스크톱 마이크와 가져온 음성 파일은 로컬 보관함의 16kHz mono PCM16 WAV로 저장한다. 입력이 끊기거나 창을 닫을 때 이미 받은 음성을 저장하거나 취소할 수 있다. 보관함 저장에 실패하면 임시 음성을 유지해 다시 저장할 수 있다
- SQLite의 오류 표시에는 녹음과 정수 표본 범위를 저장한다. 겹친 조각은 교정 목록에 넣고 기존 학습 자격을 거둔다. 교정을 확인하면 해당 전사 버전을 학습 대기열에 올린다
