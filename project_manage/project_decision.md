## PD7. 가속기를 쓰고, 쓸 수 있는 속도 안에서 가장 큰 모델을 고른다
- 날짜: 2026-11-19 04:05
- 결정: 기기의 가속기(Apple GPU, 폰 GPU 와 NPU)를 쓰고 CPU 계산은 SIMD 로 가속한다, 계층마다 아래 속도 기준을 넘는 후보 가운데 가장 큰(한국어 오류율이 가장 낮은) 모델을 고른다
  - 데스크톱 계층: 가속기를 쓰면 실시간의 3배 이상, 가속기 없이 CPU 만으로도 실시간 이상(기준 기기 M1 노트북)
  - 폰 계층: 폰 가속기로 실시간 이상
- 이유: 사용자가 "최대한 일단 할 수 있는 거에서 모델 크기가 컸으면" 이라고 했다, 숫자는 메인이 잡은 값이다
- 결정자: 방향은 사용자, 숫자는 메인
- 위임 근거: 사용자 2026-11-19 "이제 나한테 물어보지 말고"
- 상태: 방향 확정, 숫자 잠정(허용한 작업: 이 숫자로 후보를 추리고 측정한다, 멈출 단계: 시작 모델을 앱에 고정하기 전)
- 사용자 확인: 숫자는 확인 대기
- 다시 열 조건: 측정 결과 이 기준을 넘는 후보가 없거나 사용자가 다른 숫자를 줄 때
- 영향: #3, PD9, 전파: #3 board
- 확인한 사실: 3B 크기는 CPU 에서 빠르지 않다, 공개 수치로 1.7B 가 노트북 CPU 에서 실시간의 약 2배, 0.8B 가 약 2배, 0.6B 가 4코어 서버 CPU 에서 실시간과 비슷하다(기기와 출처가 서로 달라 #3 에서 직접 잰다)

## PD8. 라벨 없이 모델을 키우는 방향
- 날짜: 2026-11-19 04:05
- 결정: 아래 신호를 쌓아 가고, 어느 것이 실제로 오류율을 낮추는지는 모의실험(#4)으로 고른다
  1. 큰 모델이 단 정답으로 작은 모델 가르치기: 데스크톱에서 느리지만 정확한 큰 모델이 녹음에 정답을 달고 빠른 모델이 배운다, 한계는 큰 모델의 수준까지다
  2. 맥락으로 고른 정답: 회의 전체 글과 사용자 사전(이름, 용어)을 보고 받아쓰기 후보 여럿 가운데 하나를 고른다, 새 글을 지어내지 않고 후보 안에서만 고른다, 모델이 듣는 순간에는 없던 정보(맥락)를 더하므로 큰 모델의 수준을 넘을 수 있다
  3. 스스로 단 정답에 소음을 섞어 다시 배우기: 믿을 만한 조각만 쓰고, 정답을 다는 쪽은 학습 중인 모델의 느린 평균을 쓴다
  4. 가린 소리 맞히기: 고정된 무작위 코드북을 쓰는 방식(BEST-RQ)은 기기끼리 맞출 것이 seed 하나뿐이라 FL 에 맞다
  5. 쓰면서 생기는 약한 신호: 사용자가 고친 낱말은 그 구간의 정답이다, 고치지 않고 넘어간 것은 정답으로 치지 않는다
  6. 같은 회의를 여러 기기가 들은 경우 잘 들린 쪽이 못 들린 쪽을 가르친다(뒤 단계)
- 지키는 안전장치: 서버가 공개 라벨 데이터로 라운드마다 검증해 나빠진 업데이트를 버린다, 라운드 사이에 공개 라벨 데이터로 방향을 다시 잡는다, 업데이트 크기를 자른다
- 폰 학습을 가능하게 하는 구조: 몸통은 얼려 가속기로 추론만 하고, 그 위의 작은 부분만 학습한다, 큰 모델 전체로 역전파하지 않는다
- 이유: 한 가지 신호만 쓰면 자기 오답을 굳힌다, 모델이 못 가진 정보를 주는 신호(더 큰 모델, 맥락, 사용자 수정)를 우선한다
- 결정자: 메인(Fable xhigh 계획)
- 위임 근거: 사용자 2026-11-19 "라벨링 없이도 언슈퍼바이즈드로 어떻게 성능을 높일 수 있는지 그런 걸 좀 강구하는 게 필요해"
- 상태: 잠정(허용한 작업: 모의실험과 설계, 멈출 단계: 실제 사용자 기기에서 학습을 켜기 전)
- 사용자 확인: 확인 대기
- 다시 열 조건: #4 결과가 가설과 다를 때
- 영향: #4, 뒤의 학습 엔진과 FL 서버, 전파: #4 board
- 근거 자료: FedNST(삼성, 2022, 기기의 무라벨 음성으로 FL 을 해 단어 오류율 22.5% 감소, https://arxiv.org/abs/2206.02797), 사용자가 붙여 준 ChatGPT 대화(같은 발화의 다른 조건, 겹친 말 분리 MixIT, GAN 방식 wav2vec-U 는 별도 연구로 둔다는 판단)
